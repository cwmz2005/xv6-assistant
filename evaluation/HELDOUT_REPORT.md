# 留出集实验报告

## 设计与标注来源

测试集为 `heldout.source-verified.jsonl`，八题，与六题开发集的问题不同；包含中文与英文，以及事实、源码定位、跨文件、库外问题各两题。题目和参考答案在检索前冻结，未根据本轮结果调参。

相关片段与参考答案由开发者读取当前原始 util 提交源码后核对，**不是第三方人工标注**。源码 ID 依赖本地知识库；迁移数据目录后应核对 ID 映射。正式课程结论宜扩充样本并由另一位标注者复核。

固定设置：E5-small、BGE-reranker-base、CPU、Top K=5、候选数=20、RRF=60；所有方案使用相同问题和 util 原始源码版本，同时检索教材和实验指导。生成模型、temperature=0、max_tokens=2048、reasoning_effort=low 保持一致；具体模型与数据集哈希见结果 JSON。

## 检索结果

排序指标仅对六道库内题求平均，两道库外题返回 null；没有相关文档时，不将其计为检索失败，也不把任意返回结果算作相关。延迟包含全部八题。

| 方案 | Recall@5 | MRR@5 | nDCG@5 | 平均召回 ms | 平均重排 ms |
|---|---:|---:|---:|---:|---:|
| Dense | 0.917 | 0.833 | 0.811 | 1067 | 0 |
| Hybrid | 0.833 | 0.750 | 0.718 | 629 | 0 |
| Hybrid + Reranker | 0.667 | 0.500 | 0.547 | 664 | 5423 |

这次留出集上 Dense 最好，和开发集上 Hybrid + Reranker 更好的结果相反。这说明不能把少量题目的收益当作普遍规律。标识符的词面信号并不保证 RRF 对每题都有帮助；重排序可能提升相似片段而挤出跨文件分析所需的另一个函数。

延迟是单次运行，不是稳定性能基准。模型预热不等于数据库、Python 对象和操作系统缓存完全预热；部分验证工作也可能影响调度。因此 Dense 的召回更慢不意味着 BM25 能使 Dense 加速。严谨性能研究应多轮重复、轮换顺序、隔离其他负载，并报告分位数和方差。

## 四方案问答与辅助核验

32 条真实回答见 `heldout-generation-results.json`；32 条实际模型辅助核验结果见 `heldout-judged-results.json`。所有回答的生成完成状态为 true，没有输出上限截断。

| 方案 | 回答数 | 模型辅助平均分（0–1） | 平均端到端 ms |
|---|---:|---:|---:|
| Baseline | 8 | 0.725 | 9398 |
| Dense RAG | 8 | 0.925 | 11089 |
| Hybrid RAG | 8 | 0.913 | 7931 |
| Hybrid + Reranker | 8 | 0.900 | 15619 |

**这些分数不是人工准确率。** 辅助核验使用当前生成模型自身，存在同模型自评偏差，并依赖简短参考答案，不能可靠识别全部事实错误。每条结果保存分数、理由、模型、是否独立模型和局限说明；人工评分字段保持空值，没有将检索相似度转成准确率。

分类型的模型辅助分如下，每格仅两题：

| 方案 | 事实 | 源码定位 | 跨文件 | 库外拒答 |
|---|---:|---:|---:|---:|
| Baseline | 0.500 | 0.600 | 0.800 | 1.000 |
| Dense | 1.000 | 1.000 | 0.700 | 1.000 |
| Hybrid | 1.000 | 1.000 | 0.650 | 1.000 |
| Hybrid + Reranker | 0.625 | 1.000 | 0.975 | 1.000 |

这也说明检索排序指标与答案分不是同一个目标。相关性标注只覆盖指定源码片段，未穷举教材和网页中的语义等价证据；不完整标注可能低估某些召回。反过来，答案辅助分高也不证明每个论断都被引文蕴含，生成模型可能依赖训练知识。后续人工核验应分别检查事实正确性、证据支持度和版本一致性。

本批结果提示 RAG 有助于对应参考答案，而重排收益与代价需要逐题看待。题目规模很小，且标注来自开发者，不能推断一般学生问题的准确率或宣称某个方案绝对优于其他方案。

## 复现与复核

```powershell
uv run python -m backend.evaluation.cli evaluation/heldout.source-verified.jsonl evaluation/reproduced.json --k 5 --candidates 20 --warmup
```

四方案问答可在实验面板粘贴同一 JSONL，打开“同时生成回答”和“纳入重排序方案”后运行。可重载历史结果，逐题比较参考答案、实际回答，保存核验人及评分依据，或执行明确标注局限的模型辅助核验并导出 JSON。

实验会产生真实模型 API 调用。上游超时、JSON 输出错误等必须视为运行失败，不能补造分数；模型辅助评分逐题落库，重试会跳过同一模型已完成的评分。
